## 三、架构变化

### 3.1 边缘层中间件链（最终态）

```
requestId → CORS(白名单) → securityHeaders → rateLimit(KV) → errorHandler
     ↓
/api/* → proxyToMockFallback [注入 X-Internal-Token + HTTPS guard]
     ↓ (fallback disabled 时)
剩余路由: chat, auth, pay/*, admin
```

### 3.2 INTERNAL_TOKEN 双向验证链

```
用户 → Worker (BE-135 签 token) → Node (BE-142 验 token)
                  ↑                              ↑
        INTERNAL_TOKEN env               INTERNAL_TOKEN env
        (CF Workers Secrets)            (.env / docker compose)
```

**上线顺序（已按此顺序 commit）**：
1. BE-142 先 commit（`INTERNAL_TOKEN_REQUIRED=false`，向后兼容）
2. BE-135 commit（边缘开始注入 X-Internal-Token）
3. INFRA-104 配两端 token
4. 翻 `INTERNAL_TOKEN_REQUIRED=true`（正式生效）

### 3.3 路由精简

- **之前**：apps/server 有 22 个路由文件，14 个业务 stub 返回假数据
- **之后**：14 个 stub 全部删除，`/api/*` 通过 fallback 代理到 Node 后端拿真数据
- **保留**：`auth.ts`、`pay/*`、`db/*`、`llm/providers/*`（Phase 5 上线时才接，ADR-0008）
