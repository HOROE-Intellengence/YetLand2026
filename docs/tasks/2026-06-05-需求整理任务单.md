## 分类 3 ｜温度系统一致性（前后端契约）⚠️ 优先

### 前因后果
你怀疑「主 AI 的 prompt 没贯彻温度设定，可能被某次修改覆盖」。核对代码后，问题比"被覆盖"更结构性：

- 温度**不是**写在主 prompt 模板里的。`packages/shared/src/prompts/render.ts` 的模板槽位只有 `{{prelude_card}} {{character_card}} {{boundary_clause}} {{stage_strategy}} {{recall_block}} {{cutoff_warning}}` —— **根本没有温度槽位**。
- 温度是 `atmosphereJudge` 侧袋算出一个 1-5 的整数后，由 `buildSidecarBlock()` 拼成一段 `[当前温度：N]` + 高/低温提示，在 `apps/api/src/routes/chat.ts:156` 以 `systemBase + sidecarBlock` 的形式**追加**到系统提示尾部。
- 主 prompt 模板（`getSystemTemplate()`，**后台可视化可改**）对这段温度块**没有任何消费契约**——它不知道 `[当前温度：N]` 该怎么演。唯一的行为指引是 `buildSidecarBlock` 里硬编码的两行（`>=4` 和 `<=2`），中间温度 3 没有任何指引。
- 这就是"阴阳合同"的真身：**算温度的一方（atmosphereJudge，后台可改 prompt）和用温度的一方（主 prompt 模板，后台可改）各说各话，中间靠一段 code 里硬编码的桥接块**。任何一方在后台被改，桥接都不会同步。
- 另外 `apps/api/src/prompts/assemble.ts:30` 把 `boundaryClause` 直接传了空字符串 `''` —— 边界条款实际没进主 prompt，同属"契约缺失"。

### 代码现状
- 温度计算：[atmosphere-judge.ts](apps/api/src/sidecar-ai/atmosphere-judge.ts)、prompt 在 [prompts.ts](apps/api/src/sidecar-ai/prompts.ts) 的 `ATMOSPHERE_PROMPT_V2`。
- 温度注入：[chat-pipeline.ts:151 `buildSidecarBlock`](apps/api/src/pipeline/chat-pipeline.ts:151)、[chat.ts:155](apps/api/src/routes/chat.ts:155)。
