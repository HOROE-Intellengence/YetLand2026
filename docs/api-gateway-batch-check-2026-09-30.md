## 发现并修复

真实服务的全局 requestId 中间件预设了响应头，Hono 合并响应时覆盖了网关生成的数据库调用 ID。生成和存储本身成功，但按客户端收到的 ID 访问管理员调用详情会返回 404。

修复仅在网关路由：转发结束取得实际调用 ID，同步回 Hono 上下文和响应头。原聊天中间件行为不变；客户端提供的 x-request-id 也不能覆盖数据库调用 ID。

回归将真实全局中间件加入网关测试及 HTTP smoke fixture。22 项网关测试通过，覆盖 JSON/SSE 和调用详情关联。真实补测的 JSON 响应 ID 查询详情返回 200；SSE 补测输出完整落库，详情回读成功。首次补测脚本直接在 SSE 原始分片中查找连续标记产生误判，已改为先拼接 delta；之后仅回读现有 8 条记录完成对账，没有因此再次调用模型。
