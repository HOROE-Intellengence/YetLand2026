# 通话入口与主动语音测试

功能选择页保留文字对话、通话模式、API 调用和小手机四个入口。通话模式内的「即时通话」对应原 `/api/voice` Gemini Live；「高级通话」对应原 `/api/voice-hq` 主模型 + Fish 通话链路。各自的会话、音色、登录返回路径和历史记录继续独立；两种通话页面返回通话版本选择。

运营后台「用户 → 语音记录 → 通话联通与落库测试」可选择注册账号、角色、通话版本和最多 300 字的测试文字。角色须对所选账号可访问。即时通话用文字触发真实 Gemini Live 语音回复；高级通话直接按角色绑定音色调用 Fish TTS 朗读原文，跳过文字主模型与 ASR。测试不覆盖麦克风上传、签名资产或 ASR；Fish 音色配置页既有试听用途保持不变。

管理员接口 `POST /api/admin/voice/tests` 接收以下 JSON，创建／恢复一项测试，处理中返回 202；所有读写必须携带管理员令牌：

```json
{
  "mode": "advanced",
  "userId": "已注册账号ID",
  "characterId": "该账号可访问的角色ID",
  "text": "夜深了，我会在这里陪着你。",
  "requestId": "客户端生成的UUID"
}
```

轮询 `GET /api/admin/voice/tests/:id`，使用创建响应中的 `id`。相同 requestId 和输入恢复原记录，不重复购买上游生成；同 ID 不同输入返回 409。测试最多每分钟五项，与已有通话共用最多四个处理轮次／每账号一个处理轮次的限制。新测试使用新 ID。网络超时后查询原记录；浏览器离开不会自动重新请求。

测试会话单独标记在 `voice_diagnostics` 表，轮次、音频引用、大小、时长、SHA-256 等仍使用原 `voice.sqlite` 与 Opus 文件存储。测试不写角色记忆，训练授权默认为关闭。后台列表显示「联通测试」，失败轮次和错误码同样保留。读回结果的 `persistence` 分别表示轮次记录、音频元数据和文件读取／校验是否成功；完整生成但文件损坏会显示 `AUDIO_STORAGE_CHECK_FAILED`。试听通过鉴权 `/api/admin/voice/assets/:id` 读取为 Blob，令牌不进入音频 URL。

2026-10-09 本地验证：48 项语音／管理员接口测试及 17 项场景状态测试通过，API、前台及后台类型检查和生产构建通过；浏览器验证了功能选择、两种通话入口及返回、390px 手机布局和后台测试面板。控制上游测试使用真实 SQLite／FFmpeg，覆盖生成、校验、鉴权回读、重启、幂等及失败记录。

单次真实上游探测记录保留在 `.local/voice-diagnostics-live-1791529849092/report.json` 和同目录 `voice.sqlite`。本机以 server 模式直连 Fish／Gemini Live 未完成连接，两个测试都保留失败轮次、无输出音频；随后无凭证 HTTPS 探测两个域名均超时。这不能证明部署服务器的网络状态或语音已联通。本次未部署线上，也未核验线上 ASR。
