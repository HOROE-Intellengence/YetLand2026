## 0. 决策摘要（先看这里）

本方案选择**长期路线**：不是把桌面 CSS 逐场景缩进手机，而是**改框架、从根上消除最贵的几类问题**。三个核心杠杆：

1. **PWA standalone** —— 让 App 可「添加到主屏」全屏运行，从根上消除 `100vh` 地址栏陷阱与大半键盘问题。
2. **流式/内在布局（fluid + intrinsic + container query）** —— 顺着现有「单旋钮 `--type-scale`」哲学，让核心阅读栏「尺寸无关」，从源头减少断点。
3. **手势化导航** —— 复用选角页已有的指针滑动，右缘滑入唤出抽屉，保持叙事沉浸，绕开「8 个竖排小按钮」。

### 需要确认的开放决策（已给默认建议，可推翻）

| # | 决策点 | 默认建议 | 影响 |
|---|---|---|---|
| D1 | 抽屉导航在手机上的形态 | **边缘右滑唤出 + 一个可见入口**（非底部 tab 栏） | Phase 4 |
| D2 | 是否上 Service Worker 离线缓存 | **暂不**，先只做 standalone（API 驱动的应用，SW 缓存失效风险高，单独立项再评） | Phase 1 |

## 1. 目标与成功标准

**目标**：手机浏览器用户获得与桌面同等品质、且符合移动端直觉的体验；同时让代码具备「未来新屏幕尺寸不用回头改」的结构。

**成功标准（验收口径）**：

- [ ] iPhone（含刘海/灵动岛）与主流安卓机上，对话页底部输入框**不被地址栏/Home 指示条遮挡**，键盘弹出时输入框与最新消息**始终可见**。
- [ ] 所有可点元素在触屏命中区 **≥ 44×44px**。
- [ ] 「添加到主屏」后全屏 standalone 运行，有图标、启动主题色。
- [ ] 核心阅读栏在 320px–1920px 连续无断裂；横竖屏切换无错位。
- [ ] `tokens.ts` 基础数值**零改动**（Phase 0 建立数值快照测试守住；护住未来 share/长图导出的兼容）。
- [ ] Lighthouse Mobile Performance ≥ 85；可安装性以客观口径验：DevTools→Application→Manifest 无报错、移动 Chrome 出现「添加到主屏幕」、iOS Safari 添加后全屏无地址栏（注：Lighthouse 12+ 已移除 PWA 类目，不再以其评分为准）。

## 2. 核心策略与原则

### 2.1 四条原则

1. **能删问题就别修问题**：优先用 PWA standalone、`dvh`、`env(safe-area-*)` 等「根因级」手段，而非逐处补 `@media`。
2. **流式优先，断点兜底**：默认用 `clamp()`/`min()`/`max()`/container query 做连续自适应；`@media` 只保留给真正的**布局重排**（多列→单列、rail→手势）。
3. **复用既有资产**：落地页已有汉堡菜单与 `100svh`、选角页已有指针滑动与 `prefers-reduced-motion` 回退 —— 新代码与之风格/断点一致，不另起炉灶。
4. **token 单一真理源神圣不可侵犯**：`packages/design-tokens/src/tokens.ts` 是设计 token 真理源，定位为 web + share + 长图导出的**共享基准**。**绝不**把基础 px 字号改成 `vw`/`clamp`（长图导出在无视口的渲染环境会炸）。流式只发生在 web 专属 CSS 层。
   > 现状说明：`apps/share` 目前仅 README 占位、长图导出 `longImageExport` flag 关闭（W10）、web 实际消费的是手工镜像的 `tokens.css`——`tokens.ts` 尚无运行时消费者。「三方共享」是**目标态**，本护栏是为其**预留兼容**、保住未来选项，而非守护一个已上线的依赖。

### 2.2 明确避开的反模式

- ❌ 独立 `m.` 移动站 / UA 嗅探分两套代码 —— 维护地狱。
- ❌ 把 `tokens.ts` 的 `sizes` 直接改成视口单位 —— 破坏 share/长图导出。
- ❌ 全站套底部 tab 栏 —— 对极简叙事 App 是视觉污染。
- ❌ 仅靠手势、无任何可见入口 —— 可达性事故。

## 4. 全局约定（Phase 0 产出，后续所有阶段共用）

### 4.1 断点 token

在 `packages/design-tokens/src/tokens.ts` 增加（纯常量，不影响现有消费者）：

```ts
export const breakpoints = { sm: 480, md: 768, lg: 980 } as const; // px
```

镜像到 `apps/web/src/styles/tokens.css`：

```css
--bp-sm: 480px;  --bp-md: 768px;  --bp-lg: 980px;
```

> 约定：`md`(768) 为「手机/平板」主分界，对齐选角页既有断点；`lg`(980) 对齐落地页既有断点。**新代码统一用这三档**，逐步把 640/420 等散点收敛过来。

### 4.2 web 专属流式层 `styles/fluid.css`

新建 `apps/web/src/styles/fluid.css`，在 [main.tsx](../apps/web/src/main.tsx) 中 **接在 `tokens.css` 之后** 引入。它**消费** token 的 px 值作为上/下界，**不修改** token 本身：

```css
:root {
  /* 仅大号字流式：mobile 下不至于撑爆，desktop 保持原值 */
  --fs-xl:  calc(clamp(17px, 14px + 1.4vw, 20px) * var(--type-scale) * var(--font-scale));
  --fs-2xl: calc(clamp(20px, 16px + 2.0vw, 24px) * var(--type-scale) * var(--font-scale));
  --fs-3xl: calc(clamp(24px, 18px + 3.2vw, 32px) * var(--type-scale) * var(--font-scale));
  /* 正文 md/sm 不进流式：叙事可读性优先（见 D4） */
}
```

> ⚠️ 护栏：fluid 只在 web 注入；`tokens.ts` 的 `sizes`/`proseWidth` 保持纯数字，未来的长图导出与 share 不会被流式波及。

### 4.3 安全区 + 动态视口工具

- 全局别名（`tokens.css` 或 `fluid.css`）：
  ```css
  --safe-t: env(safe-area-inset-top, 0px);
  --safe-b: env(safe-area-inset-bottom, 0px);
  --safe-l: env(safe-area-inset-left, 0px);
  --safe-r: env(safe-area-inset-right, 0px);
  ```
- 新建 `apps/web/src/hooks/useViewport.ts`，封装：
  - `isMobile` / `isCoarsePointer`（`matchMedia('(pointer: coarse)')`）
  - `keyboardInset`（监听 `window.visualViewport` 的 `resize`，算出键盘高度）
  - `prefersReducedMotion`、`lowEndDevice`（`navigator.deviceMemory`/`hardwareConcurrency` 启发式）
  - 把 `keyboardInset` 写入 `--keyboard-inset` CSS 变量，供 CSS 直接消费。

### Phase 1 · PWA standalone + 视口根因修复　[M]　★最高杠杆

**目标**：可「添加到主屏」全屏运行；干掉 `100vh` 与安全区遮挡。完成后「手机能正常用」。

| 任务 | 文件 / 细节 |
|---|---|
| 新建 `public/` + manifest | `apps/web/public/manifest.webmanifest`（`display: "standalone"`、`theme_color`、`background_color`、`name/short_name`、`start_url`） |
| 图标集 | `192/512/maskable` PNG + `apple-touch-icon` |
| 注入 manifest 与 iOS meta | [index.html](../apps/web/index.html)：`<link rel="manifest">`、`apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style`、`apple-touch-icon` |
| `100vh` 基线 + `@supports`→`100svh`（**不替换**，渐进增强） | [globals.css:13](../apps/web/src/styles/globals.css)、[Conversation.module.css:4](../apps/web/src/scenes/Conversation.module.css) |
| 安全区接入所有 fixed 元素 | `.backBtn`/`.tempBadge`/`.inputBar`（Conversation）、`.rail`（DrawerRail）、`.shell`/`.closeBtn`（DrawerShell）、AchievementFlash |

**写法示例**：
```css
.wrap { height: 100vh; }                  /* 通用兜底：所有浏览器都认 */
@supports (height: 100svh) {              /* 现代浏览器：用最小视口高，护住底部输入框不被地址栏顶掉 */
  .wrap { height: 100svh; }
}
.backBtn { top: calc(12px + var(--safe-t)); left: calc(16px + var(--safe-l)); }
.inputBar { padding-bottom: calc(28px + var(--safe-b)); }
```
> ⚠️ 必须保留 `100vh` 基线、再用 `@supports` 渐进增强——**不能**直接把 `100vh` 替换成 `100dvh`：旧浏览器不认 `dvh` 会丢弃该声明，`.wrap` 退化为**无高度**（而非回落 100vh），布局崩。`dvh`/`svh` 同期落地（Safari 15.4 / Chrome 108），故 `@supports (height:100svh)` 为真时直接用 `svh` 即可，无需再写 `dvh`。

**验收**：iOS Safari「添加到主屏」后无地址栏、有图标/主题色；刘海机上返回键与输入框不被遮挡；DevTools→Application→Manifest 无报错、移动 Chrome 弹出「添加到主屏幕」提示（D2 不上 SW，以浏览器原生安装提示为准，不依赖 Lighthouse「Installable」审计）。
**回滚**：删 manifest link + 删 `@supports` 的 `100svh` 覆盖块（`100vh` 基线本就保留）即可，互不耦合。
