## ⚠️ 重要修订

### 修订 A — ADR-0005（2026-05-08）

**ADR-0005 取代"记忆零服务端"原则。** 见 `docs/tech/adr/0005-account-bound-state.md`。

| 领域 | 旧说法 | 新口径（ADR-0005 之后） |
|---|---|---|
| 长期记忆 | "本地 Dexie 独占，绝不上行" | 服务器是真理源；账号绑定上传；客户端 Dexie 仅做缓存 |
| UI 偏好（暗色 / 字号 / 调参） | 仅 localStorage | 服务器同步，登录恢复 |
| 嵌入向量 | 本地算 + 本地存 | **本地算 + 上传** |
| 跨设备同步 | "Phase 1 不做" | Phase 0 开始做（网页端定位） |
| 应用商店打包 | 列入 Phase 1 | **延后** — 现阶段定位网页端，打包另议 |

### 修订 B — 取消成本熔断降级（2026-05-09）

| 领域 | 旧说法 | 新口径 |
|---|---|---|
| 成本熔断降级 | 单用户日成本 > $2 降级便宜模型，> $5 当日截断 | **不做自动熔断**，成本通过 Prompt Caching + 多模型路由 + 上下文压缩 + 运营看板监控控制 |
| 用量规则 | 散落在 `constants.ts` 硬编码 | 中央化到 `policy_kv` 表，运营 `#policy` 面板即时修改 |

下文凡提到"记忆零服务端 / 不上行"等表述，**以 ADR-0005 为准**；凡提到"单用户熔断 / 成本降级 / 成本截断"等表述，**以修订 B 为准**。
具体后续工作清单见仓库根 `TODOlist.md`。

### 修订 C — 新后端联动模式仅限本地/测试（2026-05-11）

`pnpm dev:server` 现在不是“纯 Workers 后端”，而是联动启动：

- `apps/api`（前身 mock-server）默认运行在 `127.0.0.1:8787`
- `apps/server` 默认运行在 `127.0.0.1:8789`
- `apps/server` 通过 `ENABLE_MOCK_FALLBACK=true` 把 `/api/*`、`/admin`、`/admin-legacy`、`/assets/*` 代理到 `apps/api`

该模式用于从“新后端入口”提前跑完整产品链路，**不代表 `apps/server` 真实业务实现完成**。生产不得开启 mock fallback。详见 `docs/tech/adr/0007-linked-server-mock-fallback.md`。

### 修订 D — 前端对话续聊与结构化输出（2026-05-18）

- 主前端不展示逐字 `chunk` 过程；`chunk` 只在 `useChat` 内累计，等服务端 `structured` 事件到达后，由 `Conversation` 按 `StructuredMessagePart[]` 段落级显示：首段立即出现，后续每段间隔 0.8s。
- 前端按角色把当前设备会话快照保存到 `localStorage["yelan.chatSession.<characterId>"]`，包含 `sessionId`、messages、structured parts、round、stage、boundary、temperature；这只是当前设备续聊缓存，不是服务器真理源。
- `/api/chat` 收到前端直传的未知 `sessionId` 会自动 upsert 服务器会话行，保证后台“会话”列表能看到新对话。
- “清除本机对话”只删除本机 localStorage 快照并换新 `sessionId`，不删除服务器保存的会话、消息、长期记忆或暗号解锁状态。

### 修订 E — 邮箱 + 密码鉴权（2026-05-26）

以邮箱为首选登录标识；手机号 OTP 降级为 legacy 入口；`id` / `email` / `phone` 三者并存，零回滚现有用户。

| 领域 | 旧说法 | 新口径 |
|---|---|---|
| 登录标识 | 手机号 + 验证码 | **邮箱 + 密码**为默认；手机号 OTP / 密码登录保留；`user.id`（usr_xxx）仍是 surrogate，phone 降级 optional |
| Me 档案 | name + phone | 加 `email` / `nickname` / `avatarUrl` / `bio` + 安全位 `hasPassword` / `passwordUpdatedAt` / `phoneVerifiedAt` |
| 账户操作 | 无 | 改密 / 绑邮箱 / 改手机 / 撤销全部会话（bump tokenVersion）/ 注销（软删 `deletedAt`，已注销账号 OTP 不能复活，verify 返 410） |
| 唯一性 | phoneIndex | 加 `emailIndex`（小写）原子 swap；`PATCH /profile` 不碰 emailIndex，换登录邮箱必须走 `email/bind` |

接口：`POST /api/auth/email/{register,login}`、`/api/auth/password/{login,reset}`、`/api/me/{password,profile,email/bind,phone/change,sessions/revoke-all,delete}`。完整改动清单 / 错码表 / P1 验收见 [`docs/audit/user-account-2026-05-20.md`](audit/user-account-2026-05-20.md)。

### 修订 F — LLM 层抽包 + 记忆门控与治理（2026-05-26）

- **`@yelan/llm` workspace 包**：provider 工厂 / `LlmRouter` / pricing / think-sanitizer / stream-guard 从 `apps/api` 与 `apps/server` 上提共用，两端只各留 `create-router.ts`。详见 [`docs/structure.md`](structure.md) v0.8.0。
- **记忆门控**（`FEATURE_MEMORY_THROTTLE`，默认 off）：首轮 / stage 切换 / 关系类关键词 / 满 4 轮才注入「她记得」区块，节流降本；命中规则见 `apps/api/src/pipeline/memory-gate.ts`。
- **记忆治理**：真·遗忘连画像 / 概要一起清（写审计）；上下文滚动压缩按游标去重；画像改替换式快照 + 结构化 facts/changelog，`/api/me/memories` 回传 `profile` 给”我的画像”面板。
- 记忆通道对比（`[她记得]` vs `[用户画像]`）见 [`docs/sprint/2026-05-21-memory-channel-audit.md`](sprint/2026-05-21-memory-channel-audit.md)；prompt caching POC（NVIDIA 不支持 / horoe·Gemini 部分命中 -46% TTFT）见 [`docs/sprint/2026-05-21-prompt-caching-audit.md`](sprint/2026-05-21-prompt-caching-audit.md)。

### 修订 G — 会员 mock 闭环（2026-05-27）

- **套餐口径**：按手册推荐的「月光 / 星河 / 永夜」三档，均支持周订阅与月订阅；灰测价可在后台改周价、月价、划线价、折扣文案、赠烛数量和上下架状态。
- **支付口径**：当前不接真实微信/支付宝/Stripe，`/api/billing/subscribe` 立即生成 mock checkout 并激活本地订阅；真实支付只需把网关回调接到同一套 `activateMembership` 服务。
- **权益口径**：有效会员跳过免费对话轮次截断；订阅激活时按套餐周期赠烛，流水 reason 为 `subscription_grant`，保证以后审计能分清「后台补偿」与「订阅赠送」。
- **运营口径**：React 后台新增「会员」面板，支持套餐配置、人工开通、到期不续、近期订阅查看；写操作必须填写 reason 并落 `adminAudit`。

## 一、技术栈选型

### 选型表

| 层 | 选型 | 不选什么 | 理由 |
|---|---|---|---|
| **前端框架** | React 18 + Vite + TypeScript | 不用 Next.js | Phase 1 是 SPA 体验，SSR 价值低；Vite 启动快、构建简单；长图分享（KOC 素材）单独起一个 Next.js 子站 |
| **样式** | CSS Modules + CSS Variables | 不用 Tailwind | 手册的"暖羊皮纸/暗金/句级呼吸"是产品的命脉，Tailwind 的 utility 思维会鼓励"凑出来"，破气质。手写 CSS 让设计 token 清晰且可被设计师 review |
| **动画** | Framer Motion | 不用 GSAP | Framer 的 stagger / orchestration 直接对接句级浮现；GSAP 强但 React 生态磨合多 |
| **状态** | Zustand + React Query | 不用 Redux | 状态简单（对话流、订阅、烛态），Zustand 的 store 可被 worker 共享；服务端数据交给 React Query 自动重试 |
| **本地存储** | Dexie.js（IndexedDB 包装） | 不用裸 IndexedDB | 手册要求"百万级向量"，Dexie 的索引和事务包装节省两周心智 |
| **嵌入模型** | `transformers.js` + `bge-small-zh-v1.5`（约 90MB） | 不用 OpenAI Embedding | 浏览器本地算嵌入（隐私+成本），向量上传服务端存储（ADR-0005）。低端设备降级为关键词 BM25 |
| **后端** | Hono + Node 20（部署在 Cloudflare Workers） | 不用 Express，不用 NestJS | Workers 边缘节点 = 低延迟流式输出；Hono 是 Workers 原生最佳；NestJS 重，DI 在小团队是负债 |
| **数据库** | PostgreSQL（Neon/Supabase 托管）+ Redis（Upstash） | 不用 MongoDB | 订阅/代币是强一致性事务；Neon 按用量计费，前期几乎零成本 |
| **AI 网关** | 自建 LLMRouter（薄抽象） | 不用 LiteLLM | LiteLLM 抽象太厚、依赖重；自建 200 行代码即可，模型路由策略是核心资产，不外包 |
| **流式** | Server-Sent Events (SSE) | 不用 WebSocket | 单向流就够；SSE 在 Cloudflare Workers / 浏览器都是一等公民 |
| **支付** | 微信支付 H5/Native + 支付宝 + Stripe（Phase 2 海外） | 不接苹果内购 | Web 端绕过应用商店是手册第 10 节核心策略 |
| **监控** | Sentry（前端） + Grafana Cloud（后端指标） + 自建成本看板 | 不用阿里云全家桶 | 团队小，托管 SaaS 比自运维 ELK 便宜得多 |
| **CI/CD** | GitHub Actions + Cloudflare Pages | — | 前后端同 monorepo，pnpm workspace |

### 被手册影响的关键架构决策

1. **记忆在前端嵌入计算，服务器是真理源**（ADR-0005）。嵌入向量在浏览器本地算，加密上行到服务端存储。跨设备登录恢复记忆。
2. **Prompt 在 Workers KV，不在前端代码**（修订 #22）。前端只见到模型名、温度等元数据，看不到 system prompt 的全文。
3. **成本必须在每次 LLM 调用前/后落库**（手册风险节"高"）。这是熔断的前提。

## 三、核心模块技术拆解

### 1. 对话流水线（产品的心脏）

**Phase 1 简化版（手册修订 #4）**:3 个 AI + 规则引擎

```
用户输入
  ↓
[规则引擎] 阶段判定（关键词 + 轮次 + 时间）→ daily/rise/climax/after
  ↓
[规则引擎] 情绪守门（黑名单/极端内容拦截）
  ↓
[LLMRouter] 选模型
  ├─ daily/rise → DeepSeek-V3 或 Qwen-Max（便宜，~¥0.001/1K tokens）
  └─ climax/after → Claude Sonnet 4 或 GPT-4o（贵，~¥0.02/1K tokens）
  ↓
[主 AI] system_prompt + 角色卡 + 检索召回的记忆 + 历史 + 用户输入 → SSE 流
  ↓
[修饰分段 AI 异步] 把流出文字按"句"切，加入 0.8s 关键句停顿元数据
  ↓ （前端 SSE 消费时按 metadata 调度浮现）
  ↓
[备忘录 AI 异步, 每 N 轮触发] 提取本轮关键信息 → 向量化 → 写 IndexedDB
```

#### 关键技术细节

| 点 | 实现 | 注意 |
|---|---|---|
| **结构化段落输出** | 服务端 SSE 仍可流出 `chunk`，但前端不把 chunk 逐字展示；等待 `structured` 后按 `StructuredMessagePart[]` 渲染，首段立即出现，后续段落间隔 0.8s | 保沉浸感，避免“打字机感”破坏文本气质 |
| **关键句标注 (`glow`)** | 修饰分段 AI 用小模型扫描每句，打 emotional_intensity 0-1 分，>0.7 标 glow | 修订 #25 要求 600-800ms 额外停顿 |
| **narrative_boundary 注入** | 服务端从用户 session 读取 boundary 值（默认 2），在 system_prompt 顶部条件块拼接 | 修订 #2、#15。这是合规开关的根 |
| **Prompt Caching** | Claude/Anthropic 的 prompt caching:把"角色卡 + 系统设定"放在 prompt 头部并打 cache_control。同一角色第 2 轮起 80%+ 命中 | 手册没提，但不开 = API 成本翻 3 倍 |
| **上下文压缩** | 历史超过 8K tokens 时，调小模型把更早 N-1 轮压成 200 字摘要 | 手册技术架构节有提，需具体实现 |

### 2. 记忆系统（护城河）

```
用户首次访问
  ↓
[Web Worker] 后台下载 bge-small-zh-v1.5 (~90MB)
  ↓ 缓存到 Cache API（仅一次）
  ↓
对话每 5 轮触发一次:
  ↓
[备忘录 AI] 服务端调用，输入近 5 轮对话，输出结构化 JSON:
  {
    preferences: ["不喜欢被叫宝贝", "怕打雷"],
    events: [{date: "2026-03-12", text: "提到弟弟出事", emotion: "悲"}],
    relationship_state: "暧昧期"
  }
  ↓
[前端] 接收 JSON，对每条事实做嵌入（Worker 内）
  ↓
[Dexie] 写入两个表:
  preferences (text, embedding, weight, last_used_at)
  events (date, text, embedding, emotion, char_id)
  ↓
下轮对话开始前:
  ↓
[前端] 用当前用户输入做嵌入 → top-5 召回 → 拼到 system_prompt 的"她记得"区块
```

#### 降级策略

- 若浏览器是低端 Android（检测 `hardware_concurrency < 4` + `memory < 2GB`）→ 不下载嵌入模型，记忆系统降级为**关键词检索**（基于 jieba 分词 + BM25）。
- 若用户授权"让她记得跨设备"（Phase 2）→ 嵌入和明文加密上传，密钥仅本地。

#### 修订 #31（IF 线单向记忆）实现

```
Dexie schema 加 mode 字段:
  events { ..., mode: 'main' | 'if' }
  preferences { ..., mode: 'main' | 'if' }

读取时:
  if (current_mode === 'main') → mode === 'main'
  if (current_mode === 'if')   → mode IN ('main', 'if')

写入时:
  写到 mode === current_mode
```

简单一句过滤解决，不需要双库。

#### 对话额度与代币口径

- **对话额度** 与 **代币「烛」** 分开计算、分开入账、分开展示。
- 完全免费用户的对话额度限制为 **20 轮**；一轮 = 用户发送 1 条 + AI 完成 1 次回复。
- 代币注册时一次性发放；不做免费月度代币发放。
- 对话中触发好感、激情、高质量日常问好等轻量行为时，可发放少量代币。
- 后续支持「代币兑换对话额度」，Phase 1 仅预留账本 reason 和后台配置，不开放用户侧兑换入口。
- 所有用量规则（注册赠烛、免费轮次上限、问卷停留秒数、关键句停顿等）进入 `policy_kv` 表，由运营后台统一配置，替代 `constants.ts` 硬编码。详见 [BE-104]

#### 烛"光态"的计算（前端计算，避免服务端每次推）

```ts
function candleState(balance: number, registerGrant: number): 'full' | 'mid' | 'low' {
  // 阈值基于注册一次性发放量和后台运营配置，不再按月免费发放计算。
  if (balance > registerGrant * 0.5) return 'full';
  if (balance > registerGrant * 0.15) return 'mid';
  return 'low';
}
```

#### 幂等性

所有支付回调、注册发放、对话触发奖励、成就奖励、问卷奖励和后台补偿都走 `INSERT ON CONFLICT DO NOTHING` + 唯一索引（`gateway_event_id`, `register_grant_user_id`, `achievement_trigger_id`, `survey_completion_id`, `admin_grant_id`），避免重复发烛或重复发额度。

#### 远程运营后台

Phase 1 需要上线一个最小可用的远程后台（`/admin`），用于：

- 给注册用户发放或补偿代币「烛」，支持填写原因并写入审计日志。
- 控制用量规则（`policy_kv`）：注册赠烛数量、问卷停留秒数、关键句停顿毫秒、上下文压缩阈值等，替换 `constants.ts` 硬编码。
- 控制会员套餐：月光 / 星河 / 永夜的周价、月价、划线价、折扣文案、赠烛数量、上下架状态；灰测期支持人工开通和到期不续。
- 控制用户对话额度：查看用量统计、补偿额度。
- 控制问卷：上下线问卷、配置题目、奖励代币数量、导出结果。
- 标记特殊用户：如 `if_unlocked=true`、KOC 来源、人工观察名单。
- 查看代币账本、额度账本、问卷完成记录和基础成本报表。

### 4. 支付与合规（最危险的两块）

#### 主体问题（手册没明说但必须解决）

| 选项 | 利 | 弊 |

### 3. IF 线入口、状态机与隔离

> IF 线**仅通过后台配置的固定暗号激活**。暗号在后台 `#if-codes` 面板创建并分配批次，用户对话中输入暗号即自动进入 IF 线，不做任何系统提示。不做自然共振、开发者模式等其他入口。

#### 触发路径（仅此一条）

| 路径 | 说明 | Phase 1 |
|---|---|---|
| 叙事暗号 | 运营在后台创建暗号 → 分配给种子用户 → 用户在对话中输入 → 无声命中进入 IF 线 | P0 |

#### 状态机

```ts
type IfUnlockState =
  | 'locked'
  | 'code_matched'    // 暗号命中
  | 'entered_if'
  | 'exited_if';
```

#### 暗号规则

- 暗号在后台 `#if-codes` 面板创建（`POST /api/admin/if-codes`），设置 code、批次、来源、有效期。
- 用户对话中输入暗号 → 服务端匹配 → 不显示任何解锁提示 → 下一轮起 `narrative_boundary` 自动切换到 4、`mode='if'`。
- 用户一旦进入 IF，必须写入后台用户标记 `if_unlocked=true` + `if_source` + `if_unlocked_at`。

#### 主线污染防护

- 主线 UI 不展示“IF 线”“隐藏模式”“攻略进度”。
- 主线 Prompt 不提 IF 线存在。
- IF 线写入 `mode='if'` 记忆；主线永远不读取 `mode='if'`。
- 若合规开关降到 `boundary=1`，所有 IF 线入口立即失效，但用户主线记忆保留。

### 4. 额度、代币、成就与发放规则

- 对话中触发好感、激情、日常问好等轻量行为时，可发放少量代币。
- 后续会支持「代币兑换对话额度」，Phase 1 先预留账本 reason，不默认开放兑换入口。
