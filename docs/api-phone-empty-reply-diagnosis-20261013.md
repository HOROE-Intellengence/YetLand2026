# API 与小手机空回复排查及已发布修复

2026-10-13（America/New_York）。本机构建并部署完成，国内与 COM 入口已恢复访问。发布详情见 [部署记录](D:/YL/docs/api-phone-empty-reply-deployment-20261013.md)。

## 已确认的证据

- 对外网关检查时有 94 条调用：83 条成功且归档正文非空，6 条上游 HTTP 429，5 条上游 HTTP 500。失败发生在约 2.6–41.6 秒，不能归因于网关 180 秒超时。
- 小手机检查时有 304 条调用：300 条 complete 的上游响应含正文；4 条 CLIENT_CANCELLED，其中 3 条尚未收到正文。服务端日志不能证明正文已经在用户页面显示。
- 用户补充的表现是“生成结束，但没有新消息或出现空消息”。尚未将具体用户浏览器实例和后台请求逐条关联，因此不能把所有现象归为单一原因。
- 对外网关与小手机分别使用不同上游 Key。各发送一次合成 SSE 探针，均 HTTP 200、精确返回 YELAN_DIAG_OK 且包含 DONE；耗时分别约 3.48 秒、1.76 秒。这只验证当次短请求，不能证明间歇错误已消失。未重放真实用户提示词。

## 已发布修复范围

1. 对外网关拒绝 HTTP 200 但没有助手正文、工具调用或明确拒绝内容的 JSON；只有 role/usage/DONE 的 SSE 改为明确错误并记为失败。
2. 小手机后端校验 JSON/SSE 业务输出，识别 HTTP 200 内嵌上游错误；保留心跳、超时、日志和跨事件 JSON 碎片兼容。
3. 小手机前端识别标准 SSE error；正文经过输出正则、线上思维标签或剔除文本后变空时抛出错误，避免成功结束却不新增消息。合法工具回合和显式 [静默] 保留。

生产代码仅涉及六个文件：

- apps/api/src/services/completion-output.ts（新增）
- apps/api/src/gateway/forward.ts
- apps/api/src/phone/chat-stream.ts
- ai-virtual-phone/lib/llm-http.ts
- ai-virtual-phone/lib/sse-json.ts
- ai-virtual-phone/lib/chat-engine.ts

未更换模型、Key、额度、提示词、用户文本规则或超时参数；未增加自动重试。chat-engine.ts 已有的调用追踪改动属于前次发布，此次已以正在运行的镜像为基线，仅打包本次六个文件的补丁。
